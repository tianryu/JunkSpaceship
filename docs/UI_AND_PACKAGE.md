# UI文案与包体预算

## 用户指定的三个原则

1. UI尽量减少文字，突出关键数字、进度、图标和可操作按钮。
2. 所有文字不使用中点分隔符。程序检查使用Unicode码位0x00B7，不在文案中直接放入这个字符。
3. 减少独立素材与重复内容，控制完整发布资源大小。

## UI信息优先级

主屏首先让玩家看见资金、每秒产能、章节进度、废品和可买升级。游戏名只保留中文，不放英文副标题。首次手势提示完成后消失，之后不常驻“拖动磁铁”说明。

升级卡保留图标、2–4字名称、等级、价格，取消每卡完整效果句。详细倍率由信息按钮或点按查看详情承担，不把说明缩成难以阅读的小字。

| 场景 | 常驻短文案 | 详情层保留的必要规则 |
| --- | --- | --- |
| 主屏 | 磁力、范围、无人机、收益 | 对应升级具体效果与成本 |
| 清屏 | 清屏、广告 | 废品数量、预计资金、只清理本次在场对象 |
| 研发 | 插件图标、名称、等级、概率 | 等概率候选、满级排除、消耗机会 |
| 仓库 | 机匣数量、35.00%、100.00%、核心图标 | 失败资金、普通保底、广告未完成不消耗 |
| 广告按钮 | 看广告、必得核心、必得所选 | 完整观看要求在按钮邻近区域清楚显示 |

少文字不等于隐藏广告条件或概率。广告标识、实际奖励、消耗和普通方式仍可读。概率用两位小数；必要补偿说明允许短行。

分隔采用留白、换行、独立小卡或徽标，不用中点。源代码中的注释、配置文案、文档及最终概念图也执行这条约束。

## 官方包体限制核对

核对时间：2026年10月28日。

| 官方来源 | 原文口径 | 适用性说明 |
| --- | --- | --- |
| [小游戏审核规范5.2.2](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/review-standards/) | 小游戏包体低于20MB | 同节讨论打包工具zip；未明确单列本项目H5例外 |
| [开发概览代码包限制](https://developer.taptap.cn/minigameapidoc/dev/tutorial/overview/) | 整包不超过60M | 页面描述game.js和无DOM运行环境，与网页H5并不相同 |
| [创建小游戏5.1](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/) | 首包不超过60M+ | 该表述本身不精确，不能据此放大预算 |
| [官方接入形态说明](https://developer.taptap.cn/agents/) | H5经MCP部署，区别于Tap小游戏 | 要按本项目的H5上传能力与后台校验再次确认 |

因此不把100MB当作可用上限，也不声称已经查明所有H5游戏的统一硬上限。项目主动采用更严格的内部预算，避免依赖文档差异。

## 项目包体门槛

- 优化目标：全部运行时资源不超过10,000,000字节。
- 硬门槛：发布zip以及解压后运行资源各自低于20,000,000字节，不能只报压缩后小于20MB。
- 首屏必需资源目标不超过3,000,000字节；后续素材可以本包内延迟加载，不通过额外远程资源掩盖总量。
- 项目文档、概念原图、生成提示词、node_modules、测试结果、source map和开发工具均不进入dist。
- 平台额外上传规则以实际H5校验为准；如果更严格，继续压缩，不把20MB当作平台保证。

| 类别 | 预算 | 方案 |
| --- | ---: | --- |
| 工厂／场地背景 | 1.5MB | 一套背景，尺寸裁剪与程序染色复用 |
| 废品、磁铁、无人机、飞船 | 2.0MB | 一张或两张图集，五类废品，复用四种飞船精灵并显示五个组装里程碑 |
| UI与图标 | 0.4MB | 面板、描边和进度代码绘制；少量共享图标 |
| 中文字体 | 0.8MB | 一种字体，按实际字符子集化，保留许可证 |
| 音效和音乐 | 0.8MB | 短音效，最多一段压缩循环音乐，不用长音轨 |
| 代码、配置和必要平台组件 | 1.0MB | 不引入重型引擎；实际平台组件体积待测 |
| 优化余量 | 3.5MB | 用于编码差异和必要新增文件 |
| 合计 | 10.0MB | 以上是预算，待构建后测量 |

独立绘制对象上限初稿：一套背景、五类废品、一块磁铁、一款无人机、复用四种飞船精灵并显示五个组装里程碑、六插件图标、四导航图标和少量通用符号。翻转、旋转、缩放、染色、粒子和电弧均由程序生成；不做逐帧动画序列。

实际资源为2张PNG、一张约116KB飞船WebP图集、约89KB的寒蝉全圆体字符子集和约700KB的循环音乐；音效程序合成。音乐首次交互后延迟加载。最终准确字节以validation/package-audit.json与zip-audit.json为准。

## 打包验收

构建时生成文件大小清单，并同时记录原始总字节、zip字节、首屏依赖字节和最大的10个文件。字体先子集化，透明精灵按实际解码支持选择PNG或WebP，背景压缩后人工检查。

文件尺寸不等于运行内存。一个2048×2048 RGBA图集解码约16MiB，因此同时限制图集数量和分辨率，避免下载小而解码占用大。

验证门槛：文案扫描发现禁用字符即失败；发布资源达到20,000,000字节即失败；超过10MB目标需要在报告中解释；发现把概念图直接打包充当动态界面即失败。
